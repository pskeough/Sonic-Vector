# Sonic Vector

Sonic Vector is a local audio mastering dashboard for system-wide Windows audio equalization. It matches track metadata, genres, and Last.fm tags against a set of semantic audio profiles and derives a parametric EQ curve from them. Tracks can be named in the search box, or detected automatically from Spotify if you choose to connect it.

> **On the profile data.** The profiles this repo ships with are *hand-authored synthetic priors*, generated by `preprocess_safe.py --synthetic`. They are not crowdsourced measurements and no claim about listener benefit rests on them. Supplying a real SAFE-DB export at `data/SAFEEqualiserUserData.csv` makes the pipeline use that instead. The companion study in `C:\Research\SonicEQ` found that on descriptors outside its two well-sampled words, a flat EQ is statistically indistinguishable from every method tested, so treat the curves as a starting point for your own tuning rather than as an optimum.

The system maps target sound signatures (such as Bass Boost, Warmth, Vocal Clarity, and Loudness Compensation) using vector similarity interpolation over preprocessed semantic audio centroids. It writes these curves directly to the configuration file of the Windows Equalizer APO utility.

---

## Technical Features

* **Runs on no API keys, including now-playing.** Track detection comes from the **Windows media session** (the data behind the media flyout on your volume keys), so it sees *every* player on the machine — Spotify's desktop app, a browser tab, VLC, a game — with no account, no login and no network.
* **Playback Tracking.** Detects track changes, pause and resume, and pulls cover art straight from the OS. Spotify's Web API remains available as an alternative source, but is no longer how detection works.
* **Centroid Interpolation.** Interpolates semantic audio centroids (warm, bright, presence, punchy, airy) based on active track tags. `muddy` is treated as a defect descriptor and is never blended in as a target.
* **Headroom Safety.** The preamp is computed from the realized filter cascade, so the composite response cannot exceed 0 dBFS, and the system EQ is reset to flat on every exit path.
* **Equalizer APO Integration.** Generates and writes compliant parametric EQ curves straight to the hardware equalization path.
* **Song Caching.** Saves user-customized overrides to a local SQLite database, automatically recalling them whenever that specific track plays again.

## Prerequisites

1. **Python 3.9 or higher.** Ensure Python is added to your system environment variables.
2. **Equalizer APO.** Required for real-time hardware audio equalization on Windows. Download it here: https://sourceforge.net/projects/equalizerapo/

That is the whole list. **No API key is required to use this app, including for automatic now-playing detection.** Press play in any app and Sonic Vector picks the track up from Windows, harvests its tags, matches it and applies the curve. The search box is there for tracks you want to mix without playing them.

## How Now-Playing Works

Windows keeps a **System Media Transport Controls (SMTC)** session for every app that plays media — it is what populates the media flyout on your volume keys. Sonic Vector reads it, which means:

* **No account, no login, no network.** Nothing to sign in to and nothing to configure.
* **Every player, not one service.** Spotify's desktop app, a YouTube tab, VLC, a game. If Windows knows what it is, so does Sonic Vector.
* **Cover art included**, read from the OS as an image stream and served locally. (Not every track publishes one; players are inconsistent about it.)
* **Private sessions are a non-issue.** SMTC reports a Spotify private session like any other playback, so that entire failure mode disappears.

Pick a different source in `config.yaml` if you want to:

```yaml
now_playing:
  source: "auto"      # auto | windows | spotify | none
```

`auto` uses Windows when available and falls back to Spotify only if it is not. The Windows source needs the `winrt-*` packages from `requirements.txt`; without them the app says so in the pre-flight and falls back cleanly.

## Optional: Spotify

Since detection comes from Windows, Spotify is now **only** enrichment: its artist genres widen the tag set the matcher sees, alongside Last.fm's. The app is perfectly happy with neither.

Adding credentials also enables `now_playing.source: spotify`, which polls Spotify's Web API instead — useful if you want to follow playback happening on *another* device, which the Windows session cannot see.

You can turn it on at any time from inside the app: click **API KEYS** on the Spotify strip, paste your Client ID and Client Secret, and press **VERIFY & SAVE**. The keys are checked against Spotify before they are written to `config.yaml`, and the integration comes up immediately — no restart and no file editing. Then click **CONNECT SPOTIFY** to link your account.

To get those keys, create your own Spotify Developer App:

1. Go to the **Spotify Developer Dashboard** at https://developer.spotify.com/dashboard and log in with your Spotify account.
2. Click **Create app**.
3. Fill out the application details:
   * **App name:** Sonic Vector
   * **App description:** Local audio equalization controller
   * **APIs Used:** Select **Web API**
4. Under the **Redirect URIs** field, enter this exact address:
   ```
   http://127.0.0.1:8888/callback
   ```
   *Note: this must match the Redirect URI field in the app's setup panel exactly, punctuation and port included. The default above is what the local OAuth listener uses.*
5. Check the terms box and click **Save**.
6. On the App overview page, click **Settings**.
7. Copy your **Client ID** and click **Show client secret** to copy your **Client Secret**.

If you would rather edit the file directly, the `spotify` section of `config.yaml` takes the same three values:

```yaml
spotify:
  client_id: "PASTE_YOUR_CLIENT_ID_HERE"
  client_secret: "PASTE_YOUR_CLIENT_SECRET_HERE"
  redirect_uri: "http://127.0.0.1:8888/callback"
```

`config.yaml` is gitignored, so credentials never leave your machine.

## Installation and First Run

1. **Create and Activate a Virtual Environment:**
   ```bash
   python -m venv venv
   venv\Scripts\activate
   ```
2. **Install Dependencies:**
   ```bash
   pip install -r requirements.txt
   ```
3. **Launch the Dashboard:**
   Double-click `launch_gui.bat` or run:
   ```bash
   python web_gui_app.py
   ```
   The launcher runs a pre-flight check first and prints exactly what will and will not work, including whether Equalizer APO is actually attached to the output you are listening through.
4. **Press play.** In Spotify, a browser, anything. The dashboard picks the track up from Windows within a second or two, harvests its tags, and applies a curve. Hold the **A / B** button (or the space bar) to hear the unprocessed signal, level-matched.
5. **Or type a track** into the search box under **Now Playing** and press **ANALYZE**, to mix something without playing it.

## Desktop Icon and Taskbar

```bash
python tools/install_shortcut.py
```

That creates a Desktop shortcut and a Start Menu entry, both carrying the app icon and both launching without a console window.

**To pin it to the taskbar:** open Start, type `Sonic Vector`, right-click the result, and choose **Pin to taskbar**.

That last click has to be yours. Windows 11 removed programmatic taskbar pinning for ordinary desktop applications — there is no supported API a script can call, and the `LayoutModification.xml` route only applies at first sign-in on a fresh profile. Pinning from Start is the supported path and it takes one second.

Details worth knowing:

* Clicking the icon while the app is already running **raises the existing window** rather than starting a second server, which would fail on the bound port and look like a crash.
* The dashboard opens as a **chromeless app window** (Edge or Chrome `--app` mode) with its own taskbar button and icon, in a dedicated browser profile so your extensions and session are not involved. If no Chromium browser is found it falls back to an ordinary tab.
* **To stop it, use the POWER OFF button** in the dashboard header. Launched from the taskbar there is no console to close, and closing the app window only closes the window — the server keeps running with your EQ still applied. POWER OFF resets the system EQ to flat and exits. (Killing the process from Task Manager is a hard kill: no exit handler runs, so the last curve stays applied until the next launch clears it.)
* Because there is no console, everything is logged to `data/sonicvector.log`, and anything fatal also raises a message box. Run `launch_gui.bat` instead when you want live output.
* You can also let the browser install it: with the dashboard open in Edge or Chrome, use **Install this site as an app**. That uses `static/manifest.webmanifest` and produces a pinnable app entry too.
* `python tools/install_shortcut.py --uninstall` removes the shortcuts.

The icon is generated, not committed as a hand-drawn binary:

```bash
python tools/make_icon.py
```

The curve on it is a real EQ response, rendered through `src/dsp/render.py` — the same exact-evaluation RBJ cascade the app writes to Equalizer APO.

## Verifying It Works

```bash
python tools/run_tests.py
```

Five suites, no test framework required:

| Suite | What it pins down |
| --- | --- |
| headroom safety | no tag/style combination can exceed 0 dBFS |
| exit paths | every recoverable exit leaves the system EQ flat |
| offline usability | the console works with no Spotify account |
| windows now-playing | tracks are detected with no account and no network |
| playback pipeline | tracks are detected, mixed, written to APO, and only *your* edits are remembered |
| DSP renderer | the measuring instrument agrees with the filter maths |

The playback pipeline suite drives the real monitor thread against a scripted player, so track detection, the centroid matcher, the headroom budget and the `config.txt` writer are all the shipping code — only the two network calls are substituted.

## Notes on the Spotify API

Two things changed on Spotify's side that this app has to live with:

* **Redirect URIs** (enforced since 9 April 2025): HTTPS is required except for loopback, where HTTP is allowed but only as an explicit IP literal. `localhost` is rejected — use `http://127.0.0.1:8888/callback`. The setup panel refuses `localhost` with that explanation rather than letting you discover it as an `INVALID_CLIENT` error after logging in.
* **Audio Features / Audio Analysis / Recommendations** were retired on 27 November 2024 for any app without a pre-existing quota extension. Nothing here depends on them: the EQ comes from Last.fm tags and Spotify artist genres, both of which still work. `SpotifyAPIClient.get_audio_features` is kept only as a documented stub.
